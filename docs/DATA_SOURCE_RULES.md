# 数据来源与时点规则

## 必填时间字段

每个会变化的数据集至少记录：

- `period`：财报或统计期间；
- `as_of`：数据所代表的市场/财务时点；
- `retrieved_at`：实际获取时间；
- `timezone`：IANA 时区，例如 `Asia/Shanghai`；
- `source`：来源名称与可追溯链接或文件；
- `status`：`verified`、`conditional`、`pending` 或 `unverified`。

“最新”必须具体化为最新已核验收盘、实时盘中、盘前或盘后，不得混用。

## 信源优先级

1. 公司 IR、监管文件、交易所、政府或统计机构原文；
2. 授权的专业数据库或本地 OpenD；
3. 有明确出处和时间戳的可信新闻媒体；
4. 聚合页面、搜索摘要、社交媒体和截图，仅作待核验线索。

如果任务或页面有更严格的指定主口径，必须遵守该口径；主口径硬门失败时不得用次级来源冒充等价替代。

## 一致预期与财报比较

- 保存一致预期提供方、获取时间、样本范围和 GAAP/non-GAAP 口径。
- 实际值必须来自公司发布或监管文件，并记录发布时间。
- 比较前统一期间、币种、单位和计算口径；不可比时标记 `not_comparable`。
- 同比、环比和超过一致预期是三种不同结论，不得互相替代。

## 失败处理

- 任一硬门失败：停止对应生成或发布，保留线上已验证版本。
- 只完成本地生成：写“本地产物已生成”，不得写“线上已刷新”。
- 只获得 HTTP 200：只能证明资源可访问，不能证明日期、内容或数据已更新。
- 旧数据可以保留作历史对比，但必须显示原始日期，不得冒充本轮刷新。

## 凭据安全

- API 密钥、Token、Cookie、SSH 私钥和部署凭据不得提交仓库。
- 使用 GitHub Secrets 或托管平台环境变量；示例文件只能放占位符。
- 日志、截图和 Issue 留言不得暴露凭据或完整认证响应。
