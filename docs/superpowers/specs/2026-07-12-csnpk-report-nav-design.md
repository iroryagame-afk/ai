# csnpk 投研报告统一导航设计

日期：2026-07-12

## 目标

把 `csnpk.com` 下已经公开发布的专题、行业和公司分析报告统一汇总到 `/nav/`，并建立后续发布时同步登记、同步验收的稳定规则。

成功标准：

- 当前符合口径的公开分析报告全部出现在 `/nav/`。
- 每条导航记录包含标题、公开路径、发布日期、分类和标签。
- 页面支持搜索、分类浏览，并按发布日期倒序展示。
- 每日更新页、动态数据页、工具包和非投研内容不进入报告导航。
- 新报告发布与导航登记属于同一交付，不允许只发布报告而漏掉导航。

## 收录边界

收录以下三类独立、可长期阅读的分析内容：

1. 行业研究：例如商业航天、氦气、创新药、人形机器人、CXL、掩膜版。
2. 主题策略：例如 AI 商业化、全球 AI 算力、AI 入口重估。
3. 公司研究：例如腾讯、阿里巴巴深度分析。

明确排除：

- `CSN`、`csn2` 等每日选股或每日刷新页。
- A 股资金流、美股板块资金流等动态数据页。
- Skill 安装包、下载页和其他工具性页面。
- 儿童手册等非投研内容。
- 仅存在于本地、尚未公开发布或尚未完成公开链接核验的报告。

## 方案

使用 `nav/reports.json` 作为报告清单的唯一数据源，`nav/index.html` 在浏览器端读取并渲染。

每条记录使用以下字段：

- `id`：稳定且唯一的英文标识。
- `date`：`YYYY-MM-DD` 格式的发布日期或首次公开日期。
- `title`：面向读者的报告标题。
- `url`：相对 `/nav/` 的公开链接。
- `category`：`行业研究`、`主题策略` 或 `公司研究`。
- `tags`：用于搜索和主题识别的短标签数组。

选择显式清单而非目录自动扫描，是为了确保每日更新页和非投研内容不会被误收。选择独立 JSON 而非继续把数据写死在 HTML 中，是为了让后续发布只需增加一条结构化记录。

## 页面设计

`/nav/` 改名为“CSN 投研报告导航”。页面保留简洁的移动端适配，并包含：

- 顶部标题、收录口径说明和报告总数。
- 全文搜索框，可搜索标题、分类和标签。
- 分类筛选入口：全部、行业研究、主题策略、公司研究。
- 按分类分组的报告卡片；各组内部按日期倒序排列。
- 每条报告显示日期、标题、分类和标签。
- 数据加载失败时显示明确错误提示，不展示空白页。
- 页脚注明导航只收录已公开的非每日更新投研报告。

首批应纳入：

- AI 商业化进入第二阶段定价。
- 全球 AI 算力版图深度调研。
- AI 入口重估。
- 商业航天行业研究。
- CXL 综合分析报告。
- 氦气行业投研。
- 创新药行业深度研究。
- A 股人形机器人产业链调研。
- 掩膜版 3+2 研究卡。
- 腾讯、阿里巴巴公司深度分析。

## 发布规则

项目级 `AGENTS.md` 增加“分析报告导航”规则：

1. 新增或首次公开发布专题、行业、公司分析报告时，必须同步更新 `nav/reports.json`。
2. 每日更新页、动态数据页、工具包和非投研页面不得登记。
3. 发布完成前必须核验报告公开 URL 返回成功、`/nav/` 返回成功、JSON 可读取，且导航页面能搜索到新报告。
4. Cloudflare 可能存在缓存延迟；最终验收使用 cache-busting URL，并以公开页面回读为准。
5. 删除或更改公开路径时，必须同步更新清单，避免死链。

详细口径同时保存在 `docs/report-nav-policy.md`，便于后续维护者查阅。全局记忆只保留该项目规则的短指针，不复制完整清单。

## 验证

本地验证：

- 检查 `reports.json` 是有效 JSON，`id` 和 `url` 不重复。
- 检查所有记录字段完整，日期格式正确，分类仅使用三个允许值。
- 通过本地静态服务器打开 `/nav/`，验证加载、搜索、分类筛选和移动端布局。
- 对清单中的相对路径执行文件存在性检查。

线上验证：

- 用带时间戳查询参数的公开 URL 回读 `/nav/` 和 `/nav/reports.json`。
- 逐条检查首批报告 URL 返回成功。
- 确认页面报告数量和 JSON 条目数量一致。
- 确认每日更新页没有出现在导航中。

## 非目标

- 不把导航改造成每日行情或实时数据门户。
- 不自动抓取所有目录并猜测页面类型。
- 不在本次修改报告正文、估值数据或投资结论。
- 不改变现有报告公开路径。
