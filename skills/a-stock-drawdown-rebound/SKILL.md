# A 股回撤—反弹—波动区间回测

## 目标与边界

把个股历史日线拆成可复核的“前高→低点→反弹终点”周期，回答：

- 典型回撤幅度、反弹幅度和所需交易日；
- 反弹修复了前一段跌幅的多少；
- 哪些价格区间停留时间最长；
- 当前周期处在回撤还是修复阶段。

这是价格行为描述，不是交易策略回测。用户问“现在能不能买/明天怎么买”时，转用 `a-stock-position-timing`。

## 数据红线

1. 优先连接 Futu OpenD；只有真实连通才写 `OpenD已连接`。
2. 只纳入已收盘日 K。盘中当日 K 必须排除，并在结果中写明最后数据日。
3. 同时拉取前复权（QFQ）和后复权（HFQ）日线，只使用两者共同有效日期。
4. 长期高分红股早期 QFQ 价格可能接近零或产生假性巨幅回撤。全历史比率使用 HFQ；近年技术价位和价格区间使用 QFQ。
5. 数据不足、OpenD 未连接或复权序列异常时，标记 `未完成可靠核验`，不输出伪精确统计。

## 定义

- 默认主周期：收盘价 ZigZag，反向变动 `8%` 确认拐点。
- 敏感性：同时计算 `5% / 8% / 12%`，检查结论是否只依赖单一阈值。
- 回撤幅度：`低点 / 前高 - 1`。
- 反弹幅度：`反弹终点 / 低点 - 1`。
- 修复比例：`(反弹终点 - 低点) / (前高 - 低点)`。`100%` 表示回到前高，不等于“反弹 100%”。
- 完整修复率：周期内重新达到前高的样本占比。
- 当前未完成周期：单独标记 `ongoing`，不与已确认历史周期混为确定结论。

ZigZag 端点是事后确认，存在回看偏差。该工具不得把端点当成当时已知的买卖信号。

## 执行流程

1. 确认 A 股代码（如 `SH.600900`）和分析截止日。
2. 运行脚本拉取 QFQ + HFQ 日线：

```bash
.venv/bin/python .agents/skills/a-stock-drawdown-rebound/scripts/backtest_drawdown_rebound.py \
  --code SH.600900 --fetch
```

3. 先检查数据区间、最后交易日、有效 K 线数和当前盘中 K 是否已排除。
4. 查看 5%/8%/12% 敏感性，再用 8% 主周期给出用户结论。
5. 如公司为高分红或长期复权异常标的，明确解释“HFQ 算全历史比率，QFQ 展示近年价位”。
6. 保留 `latest_backtest.json` 和 `latest_backtest.md` 作为可复核证据。

## 输出格式

结论先行，然后按以下顺序：

1. 数据口径：数据源、日期区间、复权口径、ZigZag 阈值。
2. 核心统计：周期数、中位回撤、中位反弹、中位修复比例、完整修复率、时长。
3. 重要周期表：前高日、低点日、回撤、反弹、修复比例、状态。
4. 主要波动区间：近 5 年 QFQ 收盘价停留最密集的区间及占比。
5. 当前周期：已回撤多少、已修复多少、距前高还有多少。
6. 边界：事后拐点、样本数、分红复权和未来不可保证。

用户要求“做图”时，可将上述结果做成手机竖图，但必须把“历史描述，非预测买点”置于主结论附近，不得用“确认买”等交易指令标题。
