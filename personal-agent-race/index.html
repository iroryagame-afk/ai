个人智能体竞争：
从会回答到替你完成

Meta Muse、OpenAI Dots、Grok Bot、腾讯 LightVela、阿里千问办公等产品正在争夺“个人数字代理”入口。胜负关键不只在模型，而在长期上下文、可执行工具、可信授权、任务完成率和单位经济能否形成闭环。

研究截点：2026年10月13日｜核验口径：公开官方产品页、公司公告及少量媒体交叉核验｜状态：条件式
结论先行：这一轮竞争已经进入产品化，但尚不能据此判断谁赢得个人 Agent 市场。Meta押注低门槛、免费起步和社交分发；OpenAI押注 ChatGPT 工作上下文与云端执行；Grok Bot押注持续运行的云电脑和多 Bot 工作流；阿里已开放千问办公并持续布局 Qoder，生活事务型千问 Go 尚待官方确认；腾讯的 LightVela 是常驻云端个人 Agent，小微是微信内可执行操作的限域助手。Handy Bot 仍是未获官方确认的媒体线索；元宝虽有 Agent 功能标签，但现有证据不足，不计入。真正的领先指标应是经用户授权后的重复任务完成率、每个成功任务的总成本和持续留存，而非发布数量或模型跑分。

先说结论：Agent 像会用电脑的实习生，但还不是能独立托付的管家

你可能已经用 AI 查过资料、写过文案，也可能遇到过它把答案说得很肯定、细节却不对。现在的新变化是：AI 不只回答问题，还开始替你打开网页、整理文件、比较商品，甚至推进几步连续任务。

问题是，哪家公司做得最好？对普通人来说，答案不是谁的模型榜单更高，而是谁能把常见任务做完、让你少操心，同时不擅自发消息、付款或泄露资料。

本文的答案：截至2026年10月13日，常驻云端产品、手机执行功能、办公与编程代理已经形成不同路线。另一模型复评后，旧综合名次撤回：多数产品缺少单独的接受度与留存数据，不能据此评出“谁最受普通人欢迎”。现在能比较的是可用功能、实际获取门槛、公开权限设计与收费路径。

30秒看懂三点：
① Agent 就像能操作电脑的实习生：你给目标，它拆步骤、调用工具，再把结果交回来。
② 字节的豆包、Google Gemini、Alexa+和阿里千问拥有更自然的用户入口；但“入口大”不等于 Agent 功能已经被大量使用。
③ 现在适合让它做可检查、可撤回的杂活；涉及付款、发送、删除和重要决定，仍要自己确认。

普通人现在可以怎么用：先从“整理资料、列候选、写草稿”这类结果容易检查的任务开始；只连接完成任务必需的账号；付款、发信、下单和删除前，保留人工确认。

一、口径：什么才算“个人智能体”

本报告把个人智能体限定为：面向个人用户、可代表用户把一个目标拆成多步，并实际调用应用、网页或设备完成任务；涉及付款、发送等重要动作时，能停下来请用户确认。只在对话里回答、总结文件或生成文档，即使产品把某项功能称作“Agent”，也不足以纳入。持续记忆和后台运行是加分项，不是唯一门槛。

“Muse”按 Meta 于2026年9月推出的 Muse；“Dots”按 OpenAI 的 always-on agents；“Grok Bot”按 xAI/SpaceXAI 官方命名产品。腾讯部分按产品拆分：LightVela 是腾讯轻量云团队推出、长期在线并支持记忆和定时任务的云端个人 Agent；WorkBuddy 是办公代理；小微是微信内测的原生助手，可调用微信功能但尚无证据证明它具备长期后台代理形态；Handy Bot 目前只有媒体报道，列为待核实项目。元宝虽有助手与 Agent 功能标签，但不因此纳入个人 Agent。阿里部分覆盖 QwenWork（千问办公）、Qoder 专业编程 Agent，以及媒体报道即将发布的 Qwen Go；Qwen Go 截点时没有官方发布页，暂不计分。普通千问 App 的聊天和生成能力不自动算 Agent。截点为2026年10月13日，聚焦中美个人/工作代理，不给市场规模预测，因可比用户与收入数据尚未披露。

可证伪子问题：①谁有持续任务执行环境？②上下文如何跨会话积累？③动作权限如何分级与审计？④Agent 与原有生态交易/工作流如何连接？⑤公开使用与付费证据是否足以证明产品市场契合？⑥厂商如何覆盖模型、云资源、审核和人工升级成本？

五、产品与护城河：长期上下文只是起点

Meta · 分发与个人数据

把 Agent 放进熟悉的对话

Muse 以 Messenger/WhatsApp 式交互降低学习成本，并承诺在用户授权后跨应用记忆偏好、推进长期目标。Meta 的潜在优势是社交触达、跨设备和未来眼镜入口；劣势是用户必须信任其处理邮箱、日程、支付及个人记忆。官方提出 Confidential VM 后续计划，意味着当前隐私边界仍不能等同“平台不可见”。

OpenAI · 模型与工作上下文

让对话延伸为持续项目

Dots 将 ChatGPT 记忆、偏好和云端电脑结合，强调后台持续推进、主动反馈和跨 ChatGPT/Slack/Teams 触达。优势是既有知识工作入口、模型能力和工具连接；风险是权限连接面扩大后，提示注入、误操作、数据跨频道共享和成本/套餐边界会成为企业采购审核重点。

xAI/Cursor · 持久云桌面

从“会点网页”到可复用岗位

Grok Bot 把多个命名 Bot 放进共享云电脑，支持登录后的应用、浏览器、终端、记忆、例程和互相委派。对无 API 的遗留软件，GUI 操作有现实价值；共享电脑也扩大了凭据、文件和浏览器会话的共同风险面。独立 Bot 名称不代表彼此安全隔离。

判断：“独立云电脑”是一种产品基础设施，不是护城河本身。它解决任务持续运行、网页/桌面操作和隔离主机的问题；竞争优势仍取决于成功率、恢复能力、授权体系、工具兼容、审计、单位任务成本与分发效率。

竞争可拆为五层：①基础模型与规划；②运行时、云电脑和浏览器自动化；③连接器/API/GUI 工具覆盖；④个人上下文与记忆；⑤身份、授权、审计和支付。单靠模型领先难以确保任务完成；但生态入口也不能弥补错误执行。未来的产品体验会由“完成任务的可靠性 × 用户愿意授予的权限 × 任务价值”共同决定。

六、腾讯与阿里：个人入口与垂直代理并行

八、信任与安全：Agent 获取的权限越多，产品责任越重

提示注入与网页/邮件指令

外部页面和邮件可夹带操纵指令。代理若同时读数据、持有凭据并能写入/发送，就会出现数据外泄与越权动作的组合风险。

共享会话与凭据边界

云 VM 的隔离粒度、登录凭据保存、账号切换、Cookie/文件残留和第三方连接器撤权，要能被用户理解、审计和验证。

错误动作的损失放大

下单、付款、发送、删除、公开发布、代码部署属于高影响动作。确认机制、撤销窗口、限额和异常检测决定安全成本。

Meta宣称 Muse 通过独立 Sentinel 检查互联网访问、对敏感发送/购买征求确认、提供审计轨迹，并允许用户断开服务[1]；OpenAI Dots 提供应用权限和 Custom Rules，敏感动作经 Auto-review[2]；Grok Bot有审核代理与企业网络/审计控制，但官方文档明确一个账号内所有 Bot 共用云电脑[3]。以上是厂商公开设计，不是第三方渗透测试或事故率数据。将厂商“安全、私密”表述当作已验证结果是不成立的。

推荐使用规则：只读 → 草稿 → 可撤销写入 → 需人工确认的不可逆动作。默认不给金融、医疗、身份、支付和生产环境永久权限；连接账号使用最小权限；每个高影响动作都应有清晰的对象、金额/范围、执行时间和撤销方式。

九、未来情景与证伪条件

基准情景

Agent 先在高频、边界清晰的流程中形成价值：收件箱整理、差旅草案、商品比价、内容整理、办公文档初稿、客服与代码工作流。人类继续确认有损失风险的步骤。多家产品并存，入口平台通过分发获益，专门 Agent 在垂直任务胜出。

乐观情景

可靠性和权限规范同步提升；用户愿意持续开放上下文和工具；Agent 能以低于节省价值的成本完成高频任务；交易闭环或企业自动化把价值转成可计量的增量利润。生态入口公司获得更多调用与转化，模型厂商通过订阅和企业用量变现。

悲观情景

演示任务成功、真实世界长尾失败；安全事件促使权限受限；跨平台操作常遇 MFA/CAPTCHA/界面变化；长期运行 VM 和反复重试成本高于订阅收入；用户回到聊天搜索，Agent 留存不成立。此时“个人 Agent”更可能是高级助手的功能包，而非独立产品品类。

支持升级的观察项

厂商连续披露活跃用户、90/180日留存、付费转化、任务完成率、错误率、增量 GMV/席位、每个成功任务成本；第三方基准可复现；权限、审计和数据删除经独立验证；停服迁移与故障责任有明确规则。

证伪信号

只有一次性发布和示范；使用量只报 Token/调用，不给用户或任务口径；高风险权限必须全开才能工作；重复任务仍需大量人工盯梢；定价不覆盖持续运行成本；大规模用户增长但核心业务利润不变或客服/退款损失上升。

未来季度追踪：①个人端活跃和留存是否按 Agent 功能单列；②每用户每周成功任务、人工接管率和重试成本；③阿里交易任务的增量 GMV/退货与费率；④WorkBuddy 的独立活跃、任务完成率和持续使用；元宝是否出现符合本文定义的独立执行能力；⑤Meta Muse 在美国之外的开放节奏与 Confidential VM 落地；⑥Dots 与 Grok Bot 的套餐边界、企业管理员控制和使用额度；⑦LightVela 的活跃、留存及 Handy Bot 是否正式发布；⑧Qwen Go 是否官方发布及其可执行服务范围。

十、产业与投资映射：先看谁收到了钱

当前阶段对主题投资的结论是“产业方向成立、公司利润映射需逐级验证”，不据此给出买入评级或目标价。

潜在受益链条包括：模型推理与云资源、GPU/加速器、云端隔离执行环境、浏览器/桌面自动化、身份与权限治理、企业连接器、支付与交易履约。不同公司的受益方式差异很大：云和算力可能获得用量，但需扣除自建/折扣及高峰冗余；平台型公司可能通过席位与交易转化变现，但需观察净增量与获客成本；Agent 软件商可能获得订阅，但面对模型成本下降、基础平台复制功能和安全服务支出。

判断上市公司受益应依次核实：产品/API 发布 → 真实客户使用 → 付费合同/订单 → 财报确认收入 → 毛利与现金流贡献。目前主要厂商均缺少足以比较 Agent 独立收入、单位毛利和留存的数据。模型榜单、合作新闻、活跃宣传、模型 Token 增长不能替代这条证据链。对投资者更合理的做法是跟踪财报与产品数据，避免仅凭“personal agent”概念映射到任意云、芯片或软件标的。

本节为产业研究框架，不构成证券评级、买卖建议或目标价。无股价、财务预测和估值模型支持时，不对个股做排序。
